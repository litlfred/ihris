ihris-dak-data-dictionary/v1One sheet of a WHO SMART Guidelines DAK (L2) data dictionary, derived from one iHRIS record form class. ihris-data-list/v1The records one iHRIS package ships for one list form (//I2CE/formsData/forms/<form>/<id>) in a release, each attributed to the module that ships it. `provenance` separates a module's DEFAULT data, installed with the module (e.g. ISO countries, gender), from SAMPLE data (SampleData-* modules and sites), which illustrates one country's lists and must never be read as a standard code set.by $schema tag
ihris-form-class/v1One I2CE form class (e.g. iHRIS_Person) in a release, with the fields EVERY module contributes to it merged in, and each field attributed to the module that declared it. This is the iHRIS data model: the analogue of a DAK core data element set, read from the source rather than from documentation.by $schema tag

ihris-i2ce-module/v1One I2CE module as declared by its <I2CEConfiguration> <metadata> in a specific release. Modules are the unit of iHRIS functionality: each declares what it needs (requirement), turns on (enable), refuses (conflict), and which forms and pages it contributes. Transcribed from the module's XML file inside a checksum-verified release tarball. The XML itself is not copied; `source` pins it by path and sha256.by $schema tag

ihris-source-record/v1What a version-control host says about one node of a source catalogue: a project, a release series (and its branch), a release (and its files, with checksums), or a git repository pinned at a commit. It is the companion of a `folio-catalogue-node/v1` node (reached through that node's `metadataRef`), and it exists because the catalogue-node schema is strict and has no field for an `lp:` branch, an MD5 or a commit. Nothing here is the source itself. Everything is a statement about a source that stays upstream.by $schema tag
