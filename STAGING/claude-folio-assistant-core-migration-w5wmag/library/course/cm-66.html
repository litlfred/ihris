Adding Forms

iHRIS Administrator - Level I, © IntraHealth International, CC BY 4.0. Originally offered at hrhresourcecenter.org/elearning (CapacityPlus). Licence stated by its author, the folio owner, 2026-10-09.

1. Adding Forms

This module outlines an example of adding a new form to iHRIS Manage including:

  • creating a module to contain functionality
  • creating a form
  • adding fields to the form
  • relating the form to other forms

2. Gather Requirements

Discuss the client's information needs to determine the form requirements:

  • example: an HR manager requests information on the dependents for each employee, including the name and birth date

The next step is to develop a use case based on these requirements.

3. Form Use Case

1A. Use Case Number: DEP-1

1B. Use Case Title: Add Person's Dependents

  1. Level: User-level

  2. Primary Actor: HR Staff

  3. Context of Use: The user adds information about a person's dependent to the system

  4. Preconditions: The user must be logged in and a personnel record must be visible

  5. Success Guarantee: The dependent is added to the system and can be seen in their personnel record.

  6. Main Success Scenario (MSS):

  7. The user chooses to add a new dependent to the system

  8. The user adds the dependent's name, date of birth and gender

  9. The user saves the record

  10. The dependent is now shown in the personnel page

4. Form Use Case

  1. Extensions:

1a. The user chooses to edit the information on an existing dependent

2a. The system determines that no name is set for the dependent

  1. The system displays an error message

5. Creating a Module for Forms

Adding and editing the example "dependents" in the system is a discrete function and should be put in a module:

  • in this case, this new module should be dependent on the person module
  • you need to define the form created (the dependent form)

The module will need an associated module class that shows "dependents" in the "view person page".

6. Creating a Module for Forms

Create a submodule of the site.

Create module via file configuration.xml: sudo chown -R whoami:whoami /var/lib/iHRIS/sites/manage cd /var/lib/iHRIS/sites/manage/modules mkdir dependent cd dependent gedit dependent.xml

The path /var/lib/iHRIS/sites/manage may be different depending on your installation.

7. Configuration .xml

<?xml version="1.0"?> <!DOCTYPE I2CEConfiguration SYSTEM "I2CE_Configuration.dtd"> <I2CEConfiguration name='my-dependents'> <metadata> <displayName>Person's Dependents</displayName> <className>My_Module_Dependents</className> <description>Adds Dependent Information to a Person</description> <version>4.0.3.0</version> <requirement name='Person''> <atLeast version='4.0'/> <lessThan version='4.1'/> </requirement> </metadata> <configurationGroup name='my-dependents' path='/'> <!-- INSERT INFORMATION ABOUT FORM CLASS/FORM/TASKS HERE --></configurationGroup> </I2CEConfiguration>

11. The Form

<configurationGroup name='dep_form' path='/modules/forms/forms/mydependent'> <configuration name='class'> <value>My_Dependent</value> </configuration> <configuration name='display' locale="en_US"> <value>Dependent</value> </configuration>' </configurationGroup> <configuration name='person_child_forms' path='/modules/forms/forms/person/meta/child_forms' values='many'> <value>mydependent</value> </configuration>

Register "My_Dependent" as the class associated to the form "dependent" and give it a name to display to end users.

Register "mydependent" as a child form of "person".

12. Tasks

<configurationGroup name="tasks" path="/I2CE/tasks/task_description" locale="en_US"> <configuration name="person_can_view_child_form_mydependent" locale="en_US"> <value>Can view a person's dependents</value> </configuration> <configuration name="person_can_edit_child_form_mydependent" locale="en_US"> <value>Can edit resume a person's dependents</value> </configuration> </configurationGroup>

Create a task to view and edit the dependent forms associated to a person.

Tasks are checked by the "iHRIS_PageView" class when it adds child forms to the "view" page.

If user has task, then hook is called.

13. Task Inheritance

<configurationGroup name="tasks_trickle_down" path="/I2CE/tasks/task_trickle_down/"> <configuration name="person_can_view_child_form_mydependent" values="many"> <value>person_can_view</value> </configuration> <configuration name="person_can_edit_child_form_mydependent" values="many"> <value>person_can_view_child_form_mydependent</value> <value>person_can_view</value> </configuration> <configuration name="person_can_view_child_forms" values="many"> <value>person_can_view_child_form_mydependent</value> </configuration> <configuration name="person_can_edit_child_forms" values="many"> <value>person_can_edit_child_form_mydependent</value> </configuration> </configurationGroup>

Set inheritance of tasks.

19. Existing Dependents

Child forms of person are displayed using "iHRIS_PageView".

It looks for a fuzzy method for the "iHRIS_PageView" class named "action_mydependent()".

"My_Module_Dependents" should implement "action_mydependent()" for "iHRIS_PageView".

20. Module Class

modules/dependents/lib/My_Module_Dependents.php: class My_Module_Dependents extends I2CE_Module { /** register a fuzzy method to display dependents on the view person page */ function getMethods() { return array('iHRIS_PageView->action_mydependent'=>'show_dependents'); } function show_dependents($pageObject) { $pageObj->addChildForms('mydependent'); return true; } }

If "$this->action_mydependent()" is called in "iHRIS_PageView", then "show_dependents()" is called with the "$pageObject" as its first argument.

21. Module Class

The method addChildForms('mydependent') is a method of iHRIS_PageView which:

  • looks for the html "$node" with id "mydependent"
  • populates all of the child forms "mydependent" of the "person" form
  • for each "mydependent" form adds the HTML template file "view_mydependent.html" and associates the mydependent form for that node

22. Adding Paths

The dependents module needs the following files:

  • lib/My_Module_Dependents.php
  • templates/en_US/view_mydependent.html

Add their directories to the search path in the "dependent.xml" configuration file just after the requirements section: <path name='templates'> <value>./templates</value> </path> <path name='classes'> <value>./lib</value> </path>

26. Editing Dependents

Editing an existing dependent and/or creating a new dependent requires a page.

There is a page class "iHRIS_PageFormParentPerson" that handles editing forms which are child forms of the parent form:

  • register the dependent page as a top-level page using HRIS_PageFormParentPerson
  • create the form_mydependent.html HTML template used by this page

27. Registering the Page

Add a new section to dependent.xml:

<configurationGroup name="dependent_page" path='/I2CE/page/mydependent'> <configuration name="style" values="single"> <value>ihris_common_page_form_parent_person</value> </configuration> <configurationGroup name="args"> <configuration name="title" values="single" locale="en_US"> <value>Add/Update Dependent Information</value> </configuration> <configuration name="page_form" values="single"> <value>mydependent</value> </configuration> </configurationGroup> </configurationGroup> </configurationGroup>

28. Registering the Page

<configurationGroup name="dependent_page" path='/I2CE/page/mydependent'> <configuration name="style" values="single"> <value>ihris_common_page_form_parent_person</value> </configuration> ....

This registers the page "mydependent" as a top-level page:

  • sets the page style to: ihris_common_page_form_parent_person
  • registers the page's class as: iHRIS_PageForm_ParentPerson

29. Registering the Page

<configurationGroup name="args"> <configuration name="title" values="single" locale="en_US"> <value>Add/Update Dependent Information</value> </configuration> <configuration name="page_form" values="single"> <value>mydependent</value> </configuration> </configurationGroup>

Sets arguments passed to the page's constructor, which are specific to the dependent page:

  • page's title
  • form that this page is editing/creating

30. Commit to Bazaar (bzr)

Once you finish making the changes:

  • test the module
  • check "bzr status" to see which files were edited
  • add the files to nzr: bzr add modules/dependent
  • commit the files to bzr: bzr commit -m "adding a dependents module"

31. Adding Additional Form Fields

To add another field to the form such as dependents' favorite colors:

  • increase module's version to 4.0.3.1
  • add a "<version>4.0.3.1</version>" where the favorite color field has been added
  • adjust the HTML template files
  • test it
  • commit the changes to bzr/launchpad: bzr commit -m "added the favorite color field to dependent form"
