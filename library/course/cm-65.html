Assessing Health Information Systems

iHRIS Administrator - Level I, © IntraHealth International, CC BY 4.0. Originally offered at hrhresourcecenter.org/elearning (CapacityPlus). Licence stated by its author, the folio owner, 2026-10-09.

1. Assessing Health Information Systems

This module outlines assessing health information systems (HIS) to:

  • determine health system strengthening priorities
  • determine what data is available
  • make existing systems interoperate

2. Components of a Health Information System

  • electronic health records (EHR)
  • human resource (HRIS)
  • taining (TIS)
  • population and census data
  • disease prevalence
  • facility resources (# patient beds, drug supply)
  • geographic information systems (GIS)

Source: http://www.who.int/healthmetrics/en/

3. Assess Existing Systems

  • is it a paper or electronic system?
  • describe existing systems.
  • get copies of paper forms.
  • how does the information flow?
  • who has access to what information?
  • who is the data authority?

Note: When assessing an HSS, consider using an existing tool such as: http://www.capacityproject.org/hris/hris-toolkit/section2.html

4. Identify Ways to Strengthen Existing Systems

  • what are the bottlenecks in the system?
  • what information is missing?
  • what information is not needed?
  • what data are of poor quality?
  • how should the information be used to make better decisions?

5. Determine How to Use HRIS Data

What reports are needed?

  • number of health workers by cadre and district
  • number of trainings attended by each employee
  • how often should these reports be generated?
  • annually, monthly, weekly
  • who needs to see this data and why?
  • planning for new hires
  • determining who should be trained
  • finding coverage gaps

6. Define HRIS Requirements

What is the requirement?

  • who has access to this data?
  • who can change this data?
  • what values should be allowed?
  • who sets these values?

How is this information related to other data?

  • example: what happens when an employee changes positions?

What is the priority for implementing?

7. Develop a Use Case

Work with the developer, users and stakeholders to develop a "use case." Use cases are living documents to be used continously throughout the development of an HRIS system to:

  • describe a work process
  • focus discussion about system actions
  • outline the functional requirements for a system
  • document the design of a system
  • generate procedures for testing a system
  • write instructions, help resources and training materials for end users

8. Use Case: Example

1A. Use Case Number: DEP-1 1B. Use Case Title: Add Person's Dependents 2. Level: User-level 3. Primary Actor: HR Staff 4. Context of Use: The user adds information about a person's dependent to the system. 5. Preconditions: The user must be logged in and a personel record must be visible. 6. Success Guarantee: The dependent is added to the system and can be seen in their personel record. 7. Main Success Scenario (MSS): 1. The user chooses to add a new dependent to the system. 2. The user addes the dependent's name, date of birth, and gender. 3. The user saves the record. 4. The dependent is now shown in the personel page. 8. Extensions: 1a. The user chooses to edit the information on an existing dependent. 2a. The system determines that no name is set for the dependent. 1. The system displays an error message 9.
