## 2. Security Principles

Security through Obscurity: The belief that a system of any sort can be secure so long as nobody outside of its implementation group is allowed to know how the security system is made.

## 3. Security Principles

Security by Design: Software that has been designed from the ground up to be secure. Malicious practices are taken as a given and care is taken to minimize the impact when a security vulnerability is discovered or on invalid user input.

## 4. Security Principles

Linus’s Law: Many eyes make all bugs shallow. This suggests there is improved security for algorithms and protocols whose details are published since more people can review the algorithms, identify flaws, and fix the flaws sooner.

## 5. Examples of Security

Foundations for cryptography, used in banking systems, follow Secure by Design.

LAMP (Linux, Apache, MySQL, PHP) follows Secure by Design and Linus's Law.

DVD copy protection, HDCP for HDMI, and many software licsensing systems have all been cracked and follow Security through Obscurity.

## 6. iHRIS and Security

iHRIS is built on the LAMP architecture.

iHRIS also follows the Secure by Design principle.

All iHRIS users have a password that must be authenticated.

iHRIS developers also ensure the physical security of the server.

## 7. iHRIS Roles and Tasks

Two Tiered Security Mechanism

Each user of the system is assigned a role:

- administrator
- guest
- HR manager
- HR staff

Each role has a list of tasks they are allowed to perform:

- add a new person
- edit position details
- create a new cadre

There are over 300 tasks in the system.

## 8. HTTPS Security and Privacy

http://

- iHRIS is web-based
- someone could listen to network traffic

https:// adds cryptographic layer

- prevents eavesdropping and tampering
- can be slightly slower
- requires more steps in configuring Apache
- unsigned certificates can cause user anxiety
