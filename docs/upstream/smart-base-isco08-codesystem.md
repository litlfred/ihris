**Title:** `ISCO08` CodeSystem holds 182 of ISCO-08's 619 groups but declares `content: complete` (and code `913` looks misplaced)

### Summary

`input/fsh/codesystems/ISCO08.fsh` declares `* ^content = #complete`, but it contains **182** codes. ISCO-08 has **619** groups: 10 major, 43 sub-major, 130 minor and 436 unit groups. The source workbook committed at `input/data/ISCO-08_EN_Structure_and_definitions.xlsx` has the same 182 rows, so the FSH faithfully reflects a workbook that is itself partial. `input/scripts/isco08_extractor.py` reads every row, so the truncation is in the data file, not the script.

Consumers that treat `content: complete` literally will reject valid ISCO-08 codes. For example, `ISCO08ValueSet` (`include codes from system $ISCO08`) currently admits only these 182.

### Evidence

**1. The hierarchy is truncated. This is visible from smart-base alone:**

- 7 unit groups have no parent minor group present: `6111`, `6112`, `6113`, `6114`, `9211`, `9212`, `9213`.
- 54 major, sub-major or minor groups have no children present, e.g. `0`, `13`, `14`, `24`, `25`, `26`, `33`, `34`, `35`, `42`, `43`, `44`, `52`, `53`, `54`, …

**2. Comparison with an independent full ISCO-08 list.** iHRIS (IntraHealth, GPL) has shipped ISCO-08 as default data since 2009 (`ihris-common` 4.3.3, modules `isco-08-major-00` … `-09`):

| | smart-base | iHRIS 4.3.3 |
|---|---|---|
| major / sub-major / minor / unit | 10 / 40 / 49 / 83 | 10 / 43 / 130 / 436 |
| total | 182 | 619 |
| orphan codes (parent absent) | 7 | 0 |

Of the 181 codes present in both, 179 have matching titles. The other 2 differ only in spelling or capitalization (`1113`, `2265`). The 438 codes missing from smart-base are all present in iHRIS.

**3. Code `913` "Helpers in Food Preparation".** smart-base has `913` under sub-major `91` "Cleaners and Helpers". It *also* has sub-major `94` "Food Preparation Assistants", but no minor group beneath `94`. iHRIS's list has `941` "Food preparation assistants" (units `9411` Fast food preparers, `9412` Kitchen helpers) and no `913`. This suggests `913` should be `941`.

*Not yet confirmed against ILO's published structure.* The ILO file the extractor cites (webapps.ilo.org) was not reachable from the environment that prepared this draft.

### Suggested fix

1. Replace `input/data/ISCO-08_EN_Structure_and_definitions.xlsx` with the complete ILO workbook, and re-run `isco08_extractor.py`.
2. Until then, set `* ^content = #fragment`, so the CodeSystem does not claim completeness.
3. Confirm `913` against the ILO structure, and correct it to `941` if the full file agrees.

python3 - <<'PY'

print("orphans:", sorted(c for c in codes if len(c) > 1 and c[:-1] not in codes))
PY
